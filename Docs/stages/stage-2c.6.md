# Этап 2c.6: интеграция онлайна в Unity

Статус: код готов 2026-11-03 (координатор сам, без исполнителя); проверено batch-тестами и smoke-прогоном плеера против настоящего сервера. **Ждёт проверки пользователя в Editor** (чек-лист ниже).

План: `Docs/Stage2c-Plan.md`, раздел 2c.6. Опора: 2c.5 (`stages/stage-2c.5.md`, раздел «Для 2c.6»).

## Что сделано
- `Craft/ClientSettingsStore.cs`: путь `persistentDataPath/orbital-client.json` (в Editor и плеере это `%USERPROFILE%/AppData/LocalLow/DefaultCompany/orbital/`). В файле адрес, позывной, токены и путь к файлу секрета; секрета нет.
- `Craft/CraftNetLink.cs` (обычный класс): `ClientSettings` + `NetSession` + `OwnCraftLink`, проводка событий как в e2e (`Stage2cNetTests.Pilot`); токен сохраняется при выдаче; строка Net для HUD (состояние, admin, RTT, масштаб, отказы, очередь, последняя коррекция); `RequestHardSync` (аппарат отстал от времени мира больше чем на 5 с → следующий серверный state берётся как есть); лог коррекций `[net] correction ...` в консоль Unity.
- `CraftSpawner`: поля `netMode` (Offline по умолчанию: офлайн как раньше) и `serverUrl` (`ws://127.0.0.1:8765/ws`; переменная `ORBITAL_SERVER_URL` главнее). В Online:
  - локального спавна нет, Enter шлёт `spawn`, но только без аппарата или после `craft_destroyed` (в полёте спавн бросил бы аппарат на сервере);
  - каждый fixed tick: `NetSession.Update`, `TimeProvider.Discipline` к серверному времени, затем шаги `OwnCraftLink` по `InputMapper` до времени мира (шаг тот же `TimeProvider.StepSeconds`; ground support как офлайн); коррекции применяются между шагами;
  - вид рисует позицию + `View.Offset` (мягкая коррекция догоняется видом, а не прыжком);
  - `Application.runInBackground = true`; `OnDestroy` закрывает сокет и возвращает `TimeProvider` в офлайн.
  - тестовые переопределения для автоматических прогонов плеера (сцена не меняется): `ORBITAL_NET_MODE=online|offline`, `ORBITAL_AUTOSPAWN=1` (спавн сам, если аккаунт без аппарата), `ORBITAL_AUTOBURN=<с>` (полный газ с SAS N секунд после первого шага, затем отсечка).
- `TimeProvider`: `ExternalTime` (`SetExternalTime`), `Discipline(target, scale, cfg)` поверх `ClockDiscipline` (меняется только темп аккумулятора; длина шага та же); `SetTimeScale` в онлайне игнорируется. Планеты идут по серверному времени (первый ping делает прыжок часов на серверное время).
- `CraftHud`: строка Net над панелью; ползунок масштаба в онлайне только у админ-сессии: шлёт `admin_set_time_scale` после 0,3 с покоя (debounce) и показывает серверный масштаб (меняется по push `time_scale`).
- Баннеры онлайна: Connecting, No craft (Enter), Server refused, CRASHED - awaiting server, DESTROYED - Enter, Another session has the control.

## Найдено smoke-прогоном и исправлено (Core/Net, общие тесты)
- **Ложные мягкие коррекции скорости ≈0,8 м/с под тягой.** Серверный state приходил на ~0,08 с впереди последней записи истории, а продление вперёд держало скорость постоянной (ошибка a·dt). Теперь `StateHistory.TrySample` за последней записью продлевает с ускорением последнего шага. Тест `Stage2c6Tests.History_AheadOfTheNewest_KeepsTheAcceleration`.
- **Жёсткая коррекция раз в секунду после крушения**: любой серверный Crashed давал Hard, даже если клиент уже разбит. Теперь оба Crashed = Ignore. Тест `Stage2c6Tests.Reconcile_BothCrashed_IsNotACorrection`.
- После исправлений: прыжок 12 с с падением и крушением — коррекций 0 (soft 0, hard 0), отказов 0; полёт 30 с под газом — 31 сегмент принят, коррекций 0.

## Чек-лист для Editor (пользователь)
Подготовка: запустить сервер (`E:\Projects\orbital-server`, как обычно; для пункта 7 админ-канал включён в `serverconfig.json`, секрет в `E:\Projects\orbital-secrets\admin-secret.txt`). На компоненте `CraftSpawner` в `Main` поставить `Net Mode = Online` (или переменная окружения `ORBITAL_NET_MODE=online` для процесса Unity), сцену можно не сохранять.
1. Play: в строке Net `Ready`, RTT и `server t` идут.
2. Enter: аппарат на площадке (баннер No craft исчезает).
3. Взлёт (X, T, R): `rej 0`, коррекции редкие и мелкие.
4. Остановить и запустить сервер в полёте: строка Net уходит в Connecting и возвращается в Ready, аппарат продолжает (одна жёсткая коррекция `hello`).
5. Разбиться: CRASHED - awaiting server → DESTROYED → Enter даёт новый аппарат.
6. Выход из Play без исключений в консоли.
7. Ползунок масштаба виден только у админа, ×10 меняет время у всех клиентов.
8. `Net Mode = Offline`: всё как раньше.

## Проверка пользователя в Editor (2026-11-03) и фидбек
Проверено пользователем (вместе с 2c.7):
- Рестарт сервера в полёте: работает (пункт 4).
- Рестарт клиента в полёте: в первом полёте аппарат разбился о землю — после обрыва связи сервер прекращает тягу (сегмент не продлевается), пользователь считает это правильным поведением; во втором полёте рестарт прошёл удачно.
- Пауза Editor: после паузы игра продолжается как после переподключения, всё корректно.
- Ползунок админа (пункт 7) не проверен: админ-канал на сервере выключен, пользователь не нашёл, как включить. Как включить: в `serverconfig.json` сервера (`OrbitServer/serverconfig.json`, копия в `OrbitServer/bin/Debug/net8.0/`) поставить `"admin": {"enabled": true, ...}` (`secretFile` уже указывает на `E:/Projects/orbital-secrets/admin-secret.txt`), перезапустить сервер; при старте он печатает `Admin channel: ENABLED (loopback connections only)`. Клиент сам читает тот же файл (`ClientSettings.AdminSecretFile`), подключение только с loopback. Подсказку стоит добавить в чек-лист / HUD.

Фидбек (к исправлению, ещё не сделано; поставлено в очередь как 2c.8, см. `GameplayPrototype.md`, «Очередь работ», п. 4a):
1. **Не ждать сервер после уничтожения.** На клиенте нужна опция сразу заспавнить новый аппарат, не дожидаясь `craft_destroyed`; при этом уничтожение подтверждается и закрепляется (клиент сообщает серверу, сервер фиксирует обломок и уничтожение немедленно). Требует новой команды или флага в протоколе (сервер) — решение пользователя 2026-11-03: доступно только когда аппарат уже разбит на сервере.
2. **Разбитый аппарат сразу уезжает от стартового стола.** Версия (по коду, не проверено): `FlightKernel.Step` для `Crashed` ничего не делает, состояние замирает в инерциальной системе, а поверхность вращается (`LandedSupport.HoldUpright` к разбитому не применяется), поэтому обломок «уезжает» со скоростью вращения поверхности. Разбитый аппарат должен стоять на поверхности (широта/долгота, как обломок у сервера).
3. → журнал 2c.7 (дёргание чужого аппарата на поверхности).
