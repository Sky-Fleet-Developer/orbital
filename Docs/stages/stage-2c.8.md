## Решения координатора (по коду)
- **Фидбек 1 (спавн сразу после крушения)**: серверу ничего не нужно, он уже умеет это с 2c.3b: `spawn` для аппарата, который на сервере уже `Crashed` и ждёт уничтожения, бросает его (обломок, `craft_destroyed` с `abandoned: true`) и спавнит новый; для неразбитого — `already_has_craft` (`GameServer.Spawn`, тест `Stage2c3bTests.Spawn_DuringTheGrace_AbandonsTheCraft_WithAWreck`). Клиент до сих пор слал `spawn` только после `craft_destroyed`. Правка клиентская: Enter доступен, когда последнее состояние своего аппарата от сервера — `crashed` с `crashedAt` (сервер подтвердил крушение); баннер это показывает.
- **Фидбек 2 и 3 (система поверхности)**: в состояние аппарата добавлено явное поле `frame` (`inertial` | `surface`). Сервер ставит `surface` для `landed` и `crashed` (позиция — точка поверхности по широте/долготе, вращается с телом), `inertial` для полёта. Клиент: состояние в системе поверхности ведётся как точка поверхности на текущее время (`Surface.Point`), ориентация поворачивается вместе с телом; не продлевается ядром и не зависит от того, опережает ли время состояния часы клиента.
  - Причина дёргания призрака (по коду): вид по закону `v_земли * Δt` — при ошибке времени состояния относительно часов клиента (состояние «из будущего» не продлевается, пока часы его не догонят) стоящий аппарат на экваторе смещается на сотни метров в секунду ошибки, вид догоняет за 0,5 с.
  - Причина ухода своего обломка: `FlightKernel.Step` для `Crashed` ничего не делал (инерциальная заморозка). Теперь `Crashed` стоит на поверхности: широта/долгота точки удара, позиция и скорость земли на каждый шаг, ориентация вращается с телом.
- Мелочь: подсказка про админ-канал в HUD (строка Net при отказе `admin_auth`) и в чек-листе.

## Что сделано
- Сервер (`orbital-server`): `enum CraftFrame { Inertial, Surface }` (`Craft.cs`), `CraftState.Frame` (на проводе `"frame": "inertial" | "surface"`); `Propagator.StateNoBurn` ставит `Surface` для landed/crashed, состояние в прожиге — `Inertial`. Тест `Stage2c8Tests` (кадр на проводе, широта/долгота обломка не меняются со временем); e2e `Stage2cNetTests.Crash_ConfirmedByTheServer_SpawnAtOnce_AbandonsTheWreck` (крушение, сервер отдаёт `crashed` + `frame: surface` + `crashedAt`, `spawn` до `craft_destroyed` даёт новый аппарат, потом приходит `craft_destroyed` старого с `abandoned` и обломком, сессия остаётся Ready).
- `Core/Flight`: `Surface.Rotation(s, from, to)` и `Surface.Pin(s, ref state, from, to)` (точка поверхности на время, ориентация поворачивается с телом, в обе стороны по времени). `FlightKernel.Step`: при крушении пишет широту/долготу точки удара; шаг `Crashed` = `Surface.Pin`, `Omega = 0`, рычаг в нуле.
- `Core/Net`: `CraftFrameDto`, `CraftStateDto.Frame` (null у старого сервера), `StateMapper.IsSurface` (слово сервера, иначе по режиму), `FromFlightState` ставит кадр. `Ghost.OnSurface`: состояние в системе поверхности ведётся `Surface.Pin` к текущему времени клиента (и назад, если состояние «из будущего»), не ядром; при новом состоянии сравнение с точкой поверхности на сейчас. `NetSession.AdminRefusal` (причина отказа `admin_auth`).
- Unity: `CraftNetLink.LastOwnServerState`, `CrashConfirmed` (последнее своё состояние от сервера — `crashed` с `crashedAt`, того же `craftId`); `Destroyed` ставится только для своего аппарата (`craft_destroyed` брошенного аппарата приходит уже после нового). `CraftSpawner`: Enter спавнит при подтверждённом крушении, баннер `CRASHED (confirmed by the server) - press Enter for a new craft now`; строка Net при отказе админа: `admin off: serverconfig.json admin.enabled = true, restart` или `admin: refused (<причина>)`.

## Не проверено и наблюдения
- Дёргание стоящего призрака глазами не проверено (в кадре не видно); тест воспроизводит причину численно.
- **Крушение чужого аппарата решает только сервер (решение пользователя 2026-11-03, сделано)**: раньше прыгающий бот на миг показывался `crashed` — призрак продлевается ядром без тяги и «разбивался» по прогнозу. Теперь `Ghost.ServerMode` — режим по последнему слову сервера (его показывает список OTHERS в `GhostPresenter`); предсказанный жёсткий удар не крушение: призрак ждёт в точке удара (физически `Landed`) до следующего состояния сервера. Тест `FlyingGhost_NeverCrashesByPrediction_OnlyByTheServer`. После правки: OrbitMathTests 632/632, сервер 290/290; Unity EditMode 834/834 (проект компилируется).
- **Найдено пользователем в Editor (2026-11-03) и исправлено**: при частых полных включениях и выключениях тяги на малой высоте мигал баннер `CRASHED (confirmed by the server)`. Причина: пока сегмент тяги не принят сервером, сервер по баллистике считает аппарат разбитым (ретро-окно, крушение ещё отменяемо); сверка правильно отбрасывала такое состояние как `Stale` (коррекций в `Editor.log` нет), но `CrashConfirmed` брал последнее состояние сервера без оглядки на клиента. Опасно: Enter в этот момент бросил бы летящий аппарат. Теперь подтверждение = клиент сам в `Crashed` **и** последнее состояние сервера `crashed` с `crashedAt` (`Reconciler.CrashConfirmed`, engine-free; тест `CrashConfirmed_OnlyWhenBothSidesHaveItCrashed`). Пока клиент летит, баннера нет и Enter ничего не делает. OrbitMathTests 633/633, сервер 290/290; Unity EditMode не перезапущен (Editor открыт), в Unity-файле `CraftNetLink.cs` одна строка вызывает новую функцию.
- **Найдено пользователем в Editor (2026-11-03): прогноз жига чужих аппаратов (сделано)**. Два аппарата стартуют вместе, чужой то обгоняет, то отстаёт. Причина: сервер знает тягу только из закрытых сегментов (онлайн до 5 с + отправка), между ними состояние чужого аппарата баллистическое, призрак падает и догоняет. Решение (по просьбе пользователя — только для ближней зоны, через существующую частую рассылку ближней группы `proximity_update`: 300 км, раз в 1 с):
  - клиент в сегменте шлёт `endThrottle` — дроссель сразу после конца сегмента (рекордер: разрез по длине/дросселю/повороту/SAS и flush — текущий дроссель, выключение двигателя — 0; `ThrustSegment.EndThrottle`, `ManeuverRequestDto.EndThrottle`);
  - сервер хранит его в `BurnRecord.EndThrottle` и только в состояниях ближней группы (`HotGroupStates`) отдаёт `thrust` (`ThrustTail`: время конца сегмента, дроссель, направление по ориентации в конце, позиция/скорость/топливо на тот момент), пока аппарат летит и с конца сегмента прошло не больше `ThrustTailSeconds` (10 с реальных × масштаб); в `get_state` всех хвоста нет;
  - призрак (`Ghost`): при хвосте начинает с состояния конца сегмента и продлевает тягу ядром до текущего времени, но не дольше `GhostConfig.ThrustTailMax` (10 с) после конца сегмента; состояние медленного канала (без хвоста) в течение `DetailedHold` (5 с) после состояния ближней группы пропускается (`CraftStateDto.Detailed`, только на клиенте); состояние ближней группы без хвоста гасит тягу сразу.
  - Тесты: `Recorder_EndThrottle_TellsWhetherTheBurnGoesOn`, `Ghost_CarriesTheBurnOn_FromTheThrustTail` (баллистика отстаёт > 50 м за 5 с, с хвостом ошибка < 5 % от этого и < 10 м: остаток от угловой скорости, которой призрак не знает), сервер `ThrustTail_OnlyInTheNearGroup_WhileTheBurnGoesOn`. OrbitMathTests 635/635, сервер 291/291, Unity EditMode 834/834. Для проверки сервер нужно пересобрать и перезапустить. Ограничение: когда пилот меняет дроссель или поворачивает внутри ещё не отправленного сегмента, призрак узнает об этом только со следующим сегментом (до ~5 с), тогда вид плавно догоняет.
- **Токен в `orbital-client.json`**: первый smoke-прогон шёл на `ws://127.0.0.1:8765/ws` с позывным `Pilot` (как Editor) против временного сервера и перезаписал токен `Pilot` для этого адреса. Если на вашем сервере есть аккаунт `Pilot`, Editor войдёт под другим позывным (`Pilot_N`). Дальнейшие прогоны шли на порт 8799, файл восстановлен из копии. Впредь smoke только на отдельном порту и позывном.

## Вне очереди: камера мышью (2026-11-03)

Просьба пользователя: обычная орбита камеры вокруг аппарата, «вверх» = гравитация.

- `CraftPresenter`: режим V «на горизонте» стал орбитальной камерой: yaw от местного востока к северу, pitch над горизонтом, up = местная вертикаль (от центра планеты). По умолчанию yaw 0, pitch 3° (почти как прежний вид). Pitch ограничен ±85° и снизу так, чтобы камера была не ниже 1 м над землёй (цель = центр масс); при снижении аппарата камера поднимается.
- Перетаскивание правой (или средней) кнопкой мыши вращает камеру; из режима «сзади» перетаскивание переключает на орбиту с того места, где камера стоит (без скачка). Колесо меняет дистанцию в обоих режимах (×0.87 за щелчок, 8..5000 м; поля `cameraMinDistance`, `cameraMaxDistance`, `cameraDragSpeed` в `CraftViewSettings`).
- `CraftInput.CameraDrag`/`CameraZoom` читают `Mouse.current` (новый Input System), только вид, не управление аппаратом. Подсказка F1 обновлена.
- Проверка: не компилировалось (Unity открыт у пользователя); ждёт проверки в Editor.
- Пользователь проверил камеру и прогноз жига (2026-11-03): всё ок; горизонтальная ось мыши инвертирована (`_yaw + drag.x`). Карданов подвес отложен целиком (решение пользователя).
