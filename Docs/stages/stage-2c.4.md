## Журнал

### 2c.4a (2026-11-03)
- Рекордер: выборка в момент t несёт дроссель шага, закончившегося в t (ядро ставит дроссель в начале шага), и направление следующего шага (ядро берёт ориентацию на начало шага). Поэтому импульс интегрируется точно: шаг от предыдущей выборки до текущей = дроссель текущей × направление предыдущей × dt. Следствия: жжение начинается и смена дросселя действует с предыдущей выборки, поворот и переключение SAS - с текущей; конец жжения - на предыдущей выборке (шаг с нулевым дросселем в сегмент не входит). `Direction`/`Throttle` сегмента - средние по импульсу, пороги сравниваются со значениями первого шага сегмента. Новые поля: `EndTime` (побитно начало следующего сегмента непрерывного жжения), `Start`/`End` (`AttitudeSample`: ориентация, ω, gyroH, накопленный расход RCS, SAS), `RecorderConfig.Online()` (5 с, отправка не чаще 0,5 с), `Flush` (закрыть открытый сегмент на последней выборке и открыть следующий с того же момента), `Clear` (забыть всё, включая предыдущую выборку). Старая перегрузка `Update` без ориентации осталась (сервер, офлайн, тесты).
- Три старых теста рекордера (`FlightTests.cs`) проверяли прежнюю семантику «значения на начало сегмента», приведены к новой с комментариями: старт после отрыва на предыдущей выборке (≈20,0 вместо 20,05), направление сегмента с покачиванием 0,5° = среднее ≈0,25°, отброшенный «хвост» короче 0,1 с теперь задаётся выборкой до шага тяги.

### 2c.4b (2026-11-03)
Новые файлы `Assets/Orbital/Core/Net/` (только клиент, сервер их не компилирует; `.meta` с новыми случайными GUID):
- `ClockSync.cs`. `ClockSync`: время сервера - прямая в локальном реальном времени `T(L) = G0 + scale*L`; пара ping/pong даёт интервал для G0 `[Ts - scale*R, Ts - scale*S]`, оценка - середина пересечения последних 8 интервалов (алгоритм Кристиана, вместо «минимального RTT» берётся пересечение: важны только самое быстрое плечо туда и самое быстрое обратно). Интервал, не пересекающий остальные, = смена базы времени (рестарт, заморозка, дрейф): старые отсчёты сбрасываются. `OnScaleChange(time, scale)` переносит интервалы на новую прямую (для push `time_scale`); pong с другим масштабом (потерянный push) перепривязывает в момент pong. `ClockDiscipline.Apply(ref GameClock, target, scale)`: длина шага не меняется, меняется скорость аккумулятора `scale*(1+clamp(0.1*err_real, ±0.05))`, мёртвая зона 2 мс, ошибка считается от непрерывного времени (с дробью шага в аккумуляторе); при ошибке больше 0,5 с × max(1, scale) часы прыгают на целое число шагов (вызывающий пересинхронизирует аппарат). Онлайн-часы нужно создавать с `minScale` не выше 0,095, иначе замедление на 5 % при масштабе 0,1 упрётся в нижнюю границу.
- `Reconciliation.cs`. `StateHistory` (кольцо 4096 шагов, без выделений, Эрмит по позициям и скоростям, топливо линейно, `Shift`, линейная экстраполяция не дальше 0,5 с за последнюю запись). `Reconciler.Compare` -> `Stale` (есть неподтверждённая тяга со стартом раньше времени состояния), `TooOld`, `Ignore` (1 м и 0,05 м/с; на земле 2 м), `Soft` (до 2 км и 20 м/с), `Hard` (больше; расхождение режима, родителя; `crashed` от сервера; состояние впереди истории). `ApplySoft` (физика сразу, история сдвигается, вид догоняет через `ViewSmoothing`, τ 0,5 с), `ApplyFuel` (топливо сервера минус сожжённое клиентом после времени состояния), `ApplyHard` (серверное состояние с ориентацией, доведённое ядром до текущего времени без ввода; рычаг дросселя остаётся у пилота; историю, рекордер и очередь чистит вызывающий).
- `Uplink.cs`. `Uplink`: stop-and-wait, строгий порядок, общий `seq` для `maneuver`/`attitude`; тело запроса строится один раз при первой отправке и при повторе не меняется (повтор после потерянного ответа даёт `duplicate`, а не `seq_conflict`); `rcsFuelUsed = накопленный(End) - база`, база сдвигается только при принятии (`duplicate` = принятие); отказ -> очередь очищается, `NeedsResync`; `control_lost` -> отправка остановлена до нового `hello`; нет ответа 5 с реального времени -> `NeedsResync`, сообщение остаётся в очереди. `Reset(craftId, lastSeq, committedUntil, rcsBaseline)` после `hello_ok`/`spawn_result`/пересинхронизации: голова с `seq <= lastSeq` считается принятой, голова с `seq = lastSeq+1` уходит тем же телом, другой аппарат очищает очередь. `EarliestPendingThrust` для реконсилятора (к нему вызывающий добавляет старт открытого сегмента рекордера). `AttitudePolicy`: только в полёте вне жжения; после отпускания клавиш поворота, при смене фазы или включении SAS, каждые 10 с при |ω| > 1e-3 или расходе RCS; не чаще 1 раза в секунду (сработавший раньше триггер ждёт); интервалы в реальных секундах (при масштабе 100 игровые 10 с - это 0,1 с реальных).
- `Ghosts.cs`. `Propagation.Advance` (ядро без ввода, SAS по состоянию только гиродином, RCS выключен: топливо не жжётся по догадке). `Ghost`: последнее серверное состояние, доведённое до текущего времени (шаг 0,02 с, разрыв больше 2 с - шаг 0,25 с); новое состояние заменяет физику сразу, показанная позиция догоняет (τ 0,5 с).

Тесты `Stage2c4bTests.cs` (25): синхронизация (1000 прогонов по 8 ping: при джиттере RTT 20 мс медиана 0,40 мс, 95 % 1,55 мс, максимум 2,62 мс; при джиттере 0..20 мс на каждом плече медиана 0,80, 95 % 3,10, максимум 5,23 мс; вывод в консоль теста), смена масштаба, потерянный push, скачок базы; дисциплина (0,2 с отставания убраны за 90 с до < 5 мс, коррекция не больше 5 %, шаг 0,02 не меняется; прыжок при 2 с; при масштабе 10 порог 5 с); история против аналитической круговой орбиты (позиция < 1 мкм, скорость < 0,1 мм/с между шагами), кольцо; пороги реконсилятора, `Stale`, земля 2 м, мягкая коррекция (после неё то же серверное состояние даёт `Ignore`, вид затухает как e^-t/τ), топливо, жёсткая коррекция; призрак против аналитики (60 с: < 1 см; разрыв 10 мин: < 1 м; новое состояние не двигает показанную позицию, за 3 с догоняет); `Uplink` (порядок и seq, база RCS, `duplicate`, отказ, таймаут с прибывшим и с потерянным сообщением, `control_lost`, новый аппарат); политика ориентации.

Критерий плана «ошибка `ClockSync` меньше 2 мс при джиттере 20 мс» выполнен для 95 % прогонов при толковании «джиттер RTT 20 мс»; при 20 мс на каждом плече 95 % - 3,1 мс (записано как есть).
