Решения по умолчанию (приняты исполнителем, отметить, если не подходят):
1. Хэш - от текста (без BOM, LF), а не от разобранных чисел: одинаков у клиента (Mono/IL2CPP, Newtonsoft) и сервера (.NET 8, System.Text.Json) без риска расхождения в разборе и печати double; переформатирование файла меняет хэш, но это лишь лишняя загрузка через `get_world`, ложного совпадения быть не может.
2. `get_world` отдаёт текст файла (`worldJson`), а не только разобранные тела: клиент сверяет хэш именно этого текста и грузит его тем же загрузчиком, что и локальный файл.
3. Клиентское дерево строится в прежних формах (`SingleCenterBranch`/`CelestialBody`/`DoubleSystemBranch`) и через float-поля `TrajectorySettings`, чтобы `WorldModel`, виды и `StaticBody` работали без изменений. Цена: числа файла должны быть float32 и `meanAnomalyDeg` = 0 (иначе предупреждение или ошибка загрузчика). Для текущего мира это точно (тест сверки со сценой побитный).
4. `orbitNu` членов барицентра клиент не берёт из файла, а выводит из масс (как всегда делал Core); различие - предупреждение. Для текущего файла различия нет.
5. Привязка к сцене по id (правило генератора от имени объекта без `[slot]`), а не по номеру слота: порядок детей в файле может меняться.
6. Расхождения файла и сцены не фатальны (сцена - только вид): тело только в файле - `LogError` (у тела нет вида и нет `StaticBody`, значит клиентская модель не видит его сферу влияния, это расходится с сервером) и пустой объект-заглушка `<Name>[slot]`; тело только в сцене - `LogWarning` и в Play mode объект выключается (в Edit mode сцена не трогается, чтобы её случайно не сохранили изменённой); радиус/вращение файла не совпадают с `BodiesTable` - `LogWarning` (клиент по-прежнему берёт радиус и вращение из таблицы).
7. Нет файла или файл не читается - `LogError` и мир со сцены, а не остановка: офлайн-тест продолжает работать, ошибка видна в логе и в smoke-проверке.
8. Модель строится в момент `TimeProvider.WorldTime`, как и раньше со сцены (эпохи сдвигаются на время загрузки). Сейчас это 0 при старте сцены, поэтому совпадает с сервером (эпоха = `epoch` файла); см. вопрос 2.
9. Генератор не перезаписывает отличающийся файл без `--force`: файл теперь источник правды и может быть правлен руками.
10. Сервер без файла настроек (`--config` на несуществующий файл) теперь всё равно ищет каталог общих конфигов, иначе `--config-dir` терялся бы, а без него не найти мир. Поставляемый `serverconfig.json` не изменился, кроме удалённой строки `worldFile`.
11. Тестовый `Fixture.World()` без вращения хранит текст и хэш настоящего файла (определение изменено только в памяти теста).

Открытые вопросы:
1. Радиус и вращение у клиента по-прежнему из `BodiesTable`, у сервера из файла мира (оба пока совпадают, клиент предупреждает о расхождении). Сделать ли файл источником и для модельных фасетов клиента (`PhysicalFacet`, `RotationFacet`), оставив таблице только вид? Тогда «один источник» будет полным.
2. `WorldModel` строит орбиты с эпохой `время загрузки + epoch` (так было со сценой). При старте сцены время 0 и всё совпадает с сервером, но в 2c.4 клиентские часы начнутся с серверного времени: тогда мир надо строить с моментом 0 (эпоха из файла как есть), иначе планеты сдвинутся на время сервера. Решение нужно до 2c.4.
3. Сцена `Main.unity` хранит своё дерево мира (поле `tree`), которое теперь используется только при источнике `Scene`; генератор импортирует из него. Если файл мира будут править руками, дерево сцены разойдётся с файлом и тест `WorldFileTests.SharedWorld_GivesTheSceneTreePositions` упадёт. Что делать тогда: обновлять дерево сцены из файла (нужен обратный конвертер), или ослабить тест до сверки с сервером, или убрать дерево из сцены совсем?
4. Хэш от текста: переформатирование файла (например, другой отступ) заставит всех клиентов скачать мир заново. Устраивает ли это, или нужен канонический хэш по числам (риск расхождения разбора double на Mono и .NET)?
5. Нужен ли `worldHash` ещё и в `pong` или в push при смене мира на работающем сервере? Сейчас мир меняется только перезапуском сервера (новый `bootId`, `hello` даст новый хэш).

### Решения пользователя по вопросам 2c.W (2026-11-03)
1. Эпоха мира: нулевая эпоха (момент отсчёта орбит) сервера записывается в конфиг мира. Клиент получает эту эпоху и строит орбиты от неё, а не от времени своей загрузки, чтобы положения планет полностью совпадали с сервером.
2. Данные тел: клиент получает данные мира с сервера, включая модельные данные (радиус, вращение). `BodiesTable` у клиента остаётся источником вида.
3. Мир в сцене: сверять только с сервером. Тест «файл против сцены» убрать или сделать необязательным, сцену не синхронизировать.
4. Хэш мира: от текста файла (как сделано).
